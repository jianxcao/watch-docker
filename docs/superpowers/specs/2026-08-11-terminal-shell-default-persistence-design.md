# 终端默认 Shell 与浏览器记忆设计

## 目标

调整 `/terminal` 页面的 Shell 选择逻辑：当 `TERMINAL_TARGET=local` 时，优先使用当前运行用户的系统默认 Shell；记住当前浏览器上一次有效的 Shell 选择；同时使用不依赖部署方式的终端目标文案。

## Shell 选择优先级

前端按照以下顺序选择 Shell：

1. 当前浏览器为该终端目标保存的上次选择，前提是后端返回的可用 Shell 列表中仍然包含它。
2. 后端识别出的系统默认 Shell。
3. 后端返回的第一个可用 Shell。

`local` 和 `host` 的选择分别保存，避免切换终端目标后误用另一个环境中不存在的 Shell。如果浏览器中保存的 Shell 已失效或被删除，则忽略该记录并使用当前系统默认值。

## 系统默认 Shell 识别

后端仍然只返回已知路径中实际存在且可执行的 Shell。目标环境的默认 Shell 按以下顺序识别：

1. 读取目标根目录的 `/etc/passwd`，查找目标运行用户的登录 Shell；如果该 Shell 存在且可执行，则将其作为默认值。
2. 如果无法取得有效的登录 Shell，则检查当前进程的 `SHELL` 环境变量；只有该路径在目标环境中存在且可执行时才使用。
3. 如果以上两项都不可用，则使用探测到的第一个可执行 Shell。

对于 `local`，目标用户就是 Watch Docker 当前进程的运行用户。因此，无论 Watch Docker 直接安装在宿主机，还是运行在 Docker 容器中，都能识别对应运行用户的默认 Shell。

对于 `host`，目标根目录是通过 `nsenter` 进入的 Linux Docker 宿主机根目录。宿主机模式目前要求 root 权限，因此读取 UID 0 用户的登录 Shell。

最终选中的 Shell 必须存在于后端返回的安全白名单中。浏览器存储的内容不能用于执行任意程序、参数或命令。

## 浏览器记忆

使用 `localStorage` 保存选择，作用域是当前浏览器和当前站点地址，不在不同浏览器或设备之间同步。

存储键包含终端目标，因此 `local` 和 `host` 分别记忆。如果浏览器处于隐私模式、禁用了存储或访问存储时发生异常，终端仍然可以正常启动，并自动回退到后端提供的默认 Shell。

只有用户主动选择了一个有效 Shell 后才保存记录。页面首次加载后端默认值时，不会错误覆盖已有的有效记录。

## 终端目标文案

终端页头部使用以下文案：

- `local`：`当前运行环境`
- `host`：`Docker 宿主机`

“当前运行环境”在两种部署方式下都成立：直接安装时表示当前机器；Docker 部署时表示 Watch Docker 容器内部。

## 测试范围

- Go 测试覆盖 `/etc/passwd` 登录 Shell 识别、环境变量回退、可执行性校验以及第一个可用 Shell 回退。
- 前端测试覆盖按终端目标生成存储键、恢复上次选择、忽略失效记录、回退到后端默认值以及浏览器存储异常。
- 保证现有终端 URL、WebSocket、前端类型检查和生产构建继续通过。
