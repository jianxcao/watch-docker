# Compose 列表筛选 URL 状态设计

## 背景

Compose 列表当前把搜索词、状态筛选、排序字段和排序方向保存在 `ComposeView` 的组件本地状态中。进入详情页后列表组件被卸载，详情页返回时又固定跳转到不带 query 的 `/compose`，因此筛选状态会恢复默认值，也无法通过链接直接打开筛选后的列表。

## 目标

- URL query 是 Compose 列表筛选与排序状态的唯一来源。
- 刷新页面、浏览器前进/后退和直接打开链接时，列表状态与 URL 一致。
- 从列表进入 Compose 详情，再通过详情页返回按钮回到列表时，保留原筛选状态。
- 默认状态保持简洁的 `/compose` URL。

## 非目标

- 不使用 Pinia 或本地存储保存筛选状态。
- 不通过 `<KeepAlive>` 缓存 Compose 列表组件。
- 不改变 Compose 数据加载、过滤规则、排序规则或列表界面。
- 不为其他资源列表统一引入 URL 状态管理。

## URL 契约

Compose 列表拥有以下 query 参数：

| 参数 | 允许值 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `search` | 任意字符串 | 空字符串 | 按项目名称搜索 |
| `status` | `running`、`exited`、`other` | 空字符串 | 按项目状态筛选 |
| `sort` | `name`、`status` | `name` | 排序字段 |
| `order` | `asc`、`desc` | `asc` | 排序方向 |

空值和默认值不写入 URL。例如，默认列表仍为 `/compose`；完整状态可以表示为 `/compose?search=nginx&status=running&sort=status&order=desc`。

query 数组值取第一个字符串。无效的 `status`、`sort` 或 `order` 按默认值处理，并在下一次状态更新时从 URL 中移除或替换为有效值。未由 Compose 列表拥有的 query 参数在更新时原样保留，避免破坏其他路由扩展。

## 架构与组件边界

### Query 状态模块

新增一个专用于 Compose 列表的 query 状态模块，负责：

- 将 `LocationQuery` 解析为类型明确的筛选状态。
- 将筛选状态序列化为最小 query，只输出非默认值。
- 合并 Compose 拥有的参数与其他既有 query 参数。

解析和序列化保持为纯函数，方便独立测试。路由替换属于页面层副作用，不放进纯函数。

### `ComposeView.vue`

- 使用 `useRoute()` 读取 query。
- 搜索、状态、排序字段和排序方向通过可写 `computed` 暴露给现有模板和事件处理函数。
- getter 从当前 `route.query` 解析值；setter 生成新状态，并调用 `router.replace()` 更新 query。
- 过滤与排序继续从这些计算状态派生，URL 因此成为唯一状态源。
- 使用 `replace` 而不是 `push`，避免搜索输入的每次按键都创建浏览器历史记录。

该变更只替换状态来源，不新增组件，也不改变 `ComposeView` 的展示职责。

### `ComposeCard.vue`

点击卡片进入 `compose-detail` 时，将当前 Compose 列表 query 一并传入详情路由。详情 URL 因而携带返回列表所需的完整上下文。

### `ComposeDetailView.vue`

详情页返回按钮跳转到 `compose` 时携带当前 query。无论详情页是从列表进入还是通过带 query 的链接直接打开，返回列表都能恢复对应筛选状态。

## 数据流

1. 用户打开 `/compose` 或带 query 的 Compose 列表链接。
2. `ComposeView` 从 `route.query` 解析筛选状态。
3. 现有 `filteredProjects` 根据解析后的状态计算列表。
4. 用户修改搜索、状态或排序时，可写计算属性通过 `router.replace()` 更新 URL。
5. 路由 query 更新触发计算属性重新求值，列表随之更新。
6. 用户进入详情时，列表 query 被复制到详情 URL。
7. 用户从详情返回时，同一 query 被复制回 `/compose`。

浏览器前进、后退或外部 URL 变化也会从第 2 步重新进入同一数据流，不需要额外的本地状态同步。

## 错误与兼容处理

- 缺失参数使用默认值。
- 不合法的枚举参数不抛错，按默认值处理。
- query 参数为数组时只读取第一个字符串；没有可用字符串时使用默认值。
- 搜索词保留用户输入内容，不执行额外的大小写或空白规范化，保持现有搜索行为。
- 路由更新失败不修改独立本地状态，因为不存在第二状态源；页面继续以当前 URL 为准。

## 测试策略

先为 query 纯函数编写失败测试，再实现生产代码。覆盖：

- 从完整 query 解析四项状态。
- 缺失或非法枚举参数回退默认值。
- query 数组值的处理。
- 默认状态序列化为空 query。
- 非默认状态序列化为预期参数。
- 更新 Compose 参数时保留无关 query 参数并移除恢复默认值的参数。

随后运行：

- 相关 Vitest 测试。
- 前端完整测试。
- `vue-tsc` 类型检查。
- 前端生产构建。

最后通过路由级手工验证检查直达链接、筛选更新、详情返回和浏览器前进/后退行为。

## 验收标准

- 访问带合法 query 的 `/compose` 会直接显示对应搜索、状态和排序结果。
- 修改任一筛选或排序控件后，URL 立即反映新状态。
- 恢复所有默认值后 URL 为 `/compose`，同时保留不属于 Compose 列表的 query 参数。
- 从筛选后的列表进入详情，再点击详情页返回按钮，筛选结果保持不变。
- 浏览器前进/后退后，控件状态、列表结果和 URL 始终一致。
- 非法 query 不导致页面错误，并按默认状态显示。
